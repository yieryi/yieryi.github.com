# 首屏 3D 重构方案（Digital Terrain Hero）

> 状态：第二版完成，视觉调优中
> 开始日期：2026-11-13
> 主计划：[`REFACTOR_PLAN.md`](./REFACTOR_PLAN.md)
> 使用说明：[`USAGE.md`](./USAGE.md)

---

## 1. 目标

把首屏从「右侧 3D 球」升级为「全屏数字地形」，让 3D 成为页面的主舞台，同时保持文字可读、性能可控、长期可维护。

核心体验：

1. 全屏 3D 场景，文字叠加在左侧。
2. 风格化雪山、山谷、河流、天空、鸟群。
3. 相机沿河谷缓慢移动，能持续看到河流和雪山。
4. 鼠标在首屏移动时，出现等高线式拖尾笔触，逐渐消散；鸟群同时向鼠标方向偏移。
5. 日间/夜间主题共享同一场景，只切换光照与配色。
6. 移动端保留 3D，但降低地形精度和 DPR，不显示鸟群。

## 2. 已确认决策

| 项目 | 决策 |
|---|---|
| 视觉风格 | **风格化数字地形**，不追求写实喜马拉雅 |
| Cornell box | **取消**，首屏不放 |
| 观测者 | **已移除**，不再做火柴人/坐标轴/屏幕标签 |
| 鼠标拖尾 | 做成**等高线笔触**，桌面端启用 |
| 鸟群 | 桌面端鸟群随机巡航，鼠标移动时向鼠标方向偏移；移动端不显示 |
| 移动端 | **必须有 3D**，不允许退化为纯静态海报；使用低画质档 |
| 相机 | `rotate_forward` 固定循环，无用户相机控制 |
| 模块化 | 拆成 `terrain / river / sky / birds / camera / trail / palette / quality` |
| 首屏布局 | 3D 全屏铺满，文字左对齐 + 渐变遮罩 |

## 3. 场景设定

### 3.1 构图

- 全屏 canvas 作为背景。
- 文字在左侧约 45%，河谷与雪山放在中右侧，避免主体被文字完全压住。
- 左侧渐变遮罩保证标题、正文、按钮可读；遮罩在中右侧快速衰减，让河流颜色透出来。
- 右下角保留极简坐标/场景标识。
- 底部保留 `Scroll` 提示。

### 3.2 地形

- 程序化 heightfield，低多边形几何 + 平滑着色。
- 雪线、岩石、谷地按高度和坡度混合；近景谷口降低山体高度，远景保留高峰。
- 河谷加宽，并在河心额外下切一道河床，保证水面始终可见、河流连续。
- 地形范围扩大到 120 × 120，河谷可以一直延伸到远处，不再在谷口外突然截断。
- 河流延伸到地形远端，并逐渐淡入雾色，避免出现悬空的河流或硬切断口。
- 远景用线性雾收边，地形边缘落在雾里，避免看到网格边界。
- 等高线用独立的 shader 按世界高度绘制（间隔约 1.3 场景单位）。
- 不再叠加三角网格线，避免陡坡上出现密集竖纹/摩尔纹。

### 3.3 天空

- 渐变天空穹顶 + 雾。
- 日间：冷白高光、浅蓝天空。
- 夜间：深蓝天空、月光、星点。
- 不使用完整大气散射，不加载 HDRI。

### 3.4 鸟群

- 桌面端 16 只低多边形鸟，用实体三角面绘制翅膀和身体（不用细线），避免和等高线混在一起。
- 参考 three.js 官方示例 [`webgl_gpgpu_birds`](https://threejs.org/examples/webgl_gpgpu_birds.html) 的 boids 规则：**分离 / 对齐 / 聚合**。原示例把鼠标当作捕食者驱赶鸟群，这里改为把鼠标当作**吸引目标**。
- 原示例使用 `GPUComputationRenderer` 处理上千只鸟；本项目只有 16 只，改为 CPU 端 boids，避免 GPGPU 的额外开销和复杂度。
- 鼠标目标放在相机前方约 21 个场景单位的平面上，保证鸟群出现在鼠标附近，且不会被山体挡住。
- 每只鸟独立做 seek + separation + alignment + cohesion + wander，因此是「相对跟随」而不是整群硬贴鼠标。
- 鼠标停止约 2.4 秒后，目标回到随机巡航路径。
- 鸟群高度会自动抬升到地形之上，避免穿山。
- 移动端不显示鸟群。

### 3.5 相机

使用 `ml-sharp/docs/camera_trajectory.md` 的 `rotate_forward`：

```text
t = (elapsed / duration) % 1
R = A_x * sin(2πt)
F = A_z * (1 - cos(2πt)) / 2
camera.position = base + right * R + forward * F
camera.lookAt(focus)
```

首屏参数：

- 周期 15 秒。
- 相机位于谷口外侧、河谷中心线上方，高度明显高于近景山脊。
- 桌面横向约 3.4、推近约 3.8；移动端约 1.6 / 1.9。
- 固定 focus，视线略微向下，重点落在河谷中段。
- 相机点每帧做地形高度检查，至少保持 1.8 个场景单位的安全距离；由于相机始终在谷口外侧，正常情况下不会触发。
- 地形材质使用双面渲染作为额外保险，即使极端情况下贴近山体也不会看到破洞。
- 无滚转、无垂直抖动。

### 3.6 鼠标拖尾

- 独立 2D canvas overlay，不使用 WebGL。
- 桌面端 `pointer: fine` 启用。
- 2–3 条细线曲线，带轻微偏移，模拟等高线/墨迹。
- 指数衰减，约 1.1 秒消散。
- `pointer-events: none`，不影响点击和选择。
- `prefers-reduced-motion` 下关闭。

## 4. 模块划分

```text
src/scripts/hero/
  index.ts        # 生命周期、编排、主题切换、指针事件
  quality.ts      # 高/低画质
  palette.ts      # 日/夜配色
  camera.ts       # rotate_forward + 地形安全距离
  terrain.ts      # heightfield + 雪线 + 河谷 + 等高线
  river.ts        # 河谷水面 + 流动高光
  sky.ts          # 天空穹顶 + 日/月 + 星点
  birds.ts        # 鸟群巡航 + 鼠标跟随
  trail.ts        # 等高线拖尾
  utils.ts        # 噪声、插值、光晕纹理
```

每个模块提供 `create / update / resize / dispose`（按需简化），由 `index.ts` 统一驱动。

## 5. 性能预算

- 首屏文字 LCP 不受 3D 阻塞。
- 3D 模块动态 `import()`。
- 地形覆盖 120 × 120，顶点/三角面数量与之前一致：桌面约 3.9 万，移动端约 1.4 万。
- 鸟群：桌面 16 只，移动端 0。
- 星点 ≤ 400。
- 无后处理；阴影关闭。
- DPR：桌面 ≤ 1.5，移动端 ≤ 1.25。
- 页面隐藏 / 离开视口暂停。
- 移动端仍渲染 3D，但降低精度和数量。

## 7.1 已知限制

- 日间地形偏白，岩石/阴影对比还可以继续加强。
- 日间河流仍会被左侧遮罩轻微洗淡。
- 河流白色流线偏图形化，后续可做更细的流动噪声。
- 移动端不显示鸟群与观测者，只保留地形/河流/天空 3D。
- 真机（iOS/Android）性能和发热尚未验证。
